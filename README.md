# 우테코 8기 프리코스 2주차 과제: 자동차 경주

## ✨ 기능 목록

---

### 📥 입력 기능

1.  **경주할 자동차 이름**
    > 경주할 자동차 이름을 입력하세요.(이름은 쉼표(,) 기준으로 구분)

    - **예외 처리**: 아래의 경우 에러를 발생시킨다.
        - 자동차 이름이 5자를 초과하는 경우
        - 자동차 이름이 1자 미만인 경우 (공백)
        - 경주할 자동차가 2대 미만인 경우
        - 중복된 자동차 이름이 있는 경우

2.  **시도할 횟수**
    > 시도할 횟수는 몇 회인가요?

    - **예외 처리**: 아래의 경우 에러를 발생시킨다.
        - 입력값이 숫자가 아닌 경우
        - 0 이하의 숫자를 입력한 경우

### 📤 출력 기능

1.  **라운드별 실행 결과**
    ```
    pobi : --
    woni : ----
    jun : ---
    ```
    - 각 라운드마다 자동차들의 누적 이동 거리를 `-` 문자로 표현하여 출력한다.

2.  **최종 우승자 안내**
    ```
    최종 우승자 : pobi, woni
    ```
    - 가장 멀리 이동한 자동차를 최종 우승자로 선정하여 출력한다.
    - 우승자가 여러 명일 경우 쉼표(`,`)를 이용해 모두 출력한다.

## 🛠️ 컴포넌트별 역할

---

-   **`InputView` / `OutputView`**
    -   콘솔 입출력을 전담하는 컴포넌트.
    -   로직을 가지지 않고, 사전에 정의된 메시지를 출력하거나 사용자 입력을 받는 역할만 수행한다.
-   **`constants` / `messages`**
    -   애플리케이션 전반에서 사용되는 상수와 메시지를 관리한다.
    -   오류 메시지, UI 문구, 이름 길이 제한 등을 포함한다.
-   **`CarParser`**
    -   사용자로부터 입력받은 자동차 이름 문자열을 파싱하는 역할을 책임진다.
    -   쉼표(`,`)를 기준으로 문자열을 분리하고 공백을 제거하여 이름 배열을 생성한다. 유효성 검증은 책임지지 않는다.
-   **`Car`**
    -   자동차의 상태(이름, 거리)와 행위(전진)를 관리하는 모델.
    -   이름과 거리는 외부에서 직접 수정할 수 없는 `private` 필드로 관리한다.
    -   `create` 정적 메서드를 통해 자체적으로 이름에 대한 유효성을 검사하며, 이를 통과해야만 객체 생성이 가능하다.
-   **`Race`**
    -   전체 경주 게임의 상태(참가 자동차, 시도 횟수, 라운드별 결과)와 비즈니스 로직을 관리하는 모델.
    -   `create` 정적 메서드를 통해 경주가 가능한 조건(자동차 대수, 시도 횟수 등)인지 자체적으로 검증한다.
    -   `startRace()` 메서드를 통해 경주를 진행하고, `formatResults()`, `findWinners()` 메서드로 가공된 결과 데이터를 외부에 제공한다.
-   **`RaceController`**
    -   사용자 입력부터 최종 결과 출력까지, 전체 애플리케이션의 흐름을 제어하는 지휘자 역할.
    -   각 컴포넌트(Model, View, Parser)에 필요한 작업을 요청하고 데이터를 전달한다.

## 🚗 실행 플로우

---

1.  **프로그램 시작**
    `npm start` 명령어로 `App.js`를 실행하면, `RaceController`의 `run` 메서드가 호출되며 전체 프로세스가 시작된다.
2.  **자동차 이름 입력**
    - **`Controller → View`**: `InputView.getCars()`를 호출해 사용자 입력을 요청한다.
    - *사용자 입력 예시*: `"pobi,woni,crong"`
3.  **입력값 파싱**
    - **`Controller → Parser`**: 입력받은 문자열을 `CarParser.parseNamesByComma()`에 전달한다.
    - *파싱 결과*: `['pobi', 'woni', 'crong']`
4.  **`Car` 객체 생성**
    - **`Controller → Model`**: 파싱된 이름 배열을 순회하며 `Car.create(name)`를 호출, `Car` 객체 배열을 생성한다.
    - *생성 결과*: `[ Car{...}, Car{...}, Car{...} ]`
5.  **시도할 횟수 입력**
    - **`Controller → View`**: `InputView.getTryCount()`를 호출해 사용자 입력을 요청한다.
    - *사용자 입력 예시*: `"5"`
6.  **`Race` 객체 생성**
    - **`Controller → Model`**: 생성된 `Car` 객체 배열과 시도 횟수를 `Race.create()`에 전달해 `Race` 객체를 생성한다.
7.  **경주 시작 및 진행**
    - **`Controller → View`**: `OutputView.printResultHeader()`를 호출해 `"실행 결과"` 헤더를 출력한다.
    - **`Controller → Model`**: `race.startRace()`를 호출해 경주를 시작한다.
    - **`Model: Race`**: 시도 횟수만큼 각 `Car`의 `race()` 메서드를 호출하며 라운드별 결과를 내부에 기록한다.
8.  **중간 결과 출력**
    - **`Controller → Model`**: `race.formatResults()`를 호출해 전체 경주 과정을 출력용 문자열로 가공한다.
    - **`Controller → View`**: 가공된 문자열을 `OutputView.printAllRoundResults()`에 전달해 콘솔에 출력한다.
9.  **최종 우승자 발표**
    - **`Controller → Model`**: `race.findWinners()`를 호출해 최종 우승자 목록을 문자열로 가공한다.
    - **`Controller → View`**: 가공된 우승자 문자열을 `OutputView.printWinners()`에 전달해 콘솔에 출력한다.

## 📚 고려했던 포인트

---

### 1. 앱의 구조
React + TS + Vite 기반의 프레임워크 위에서 개발을 해 왔기 때문에 함수형 프로그래밍과 훅 사용등이 익숙했지만, 다른 지원자 분들의 레포와 남겨주신 리뷰 등을 종합해 직관성과 관심사 분리의 맥락에서 **mvc 구조**와 **객체 지향형 프로그래밍**을 통해 **class 단위**로 메소드를 만드는게 더 적합하다고 생각해 해당 방법을 채용했습니다.

### 2. 분리와 책임
이번 과제는 지난 주차의 계산기보다 로직이 더욱 복잡해졌고, 개발 사항에도 명시된 만큼 각 메소드의 **기능을 최소화하고 분리**하는게 더욱 중요해 보였습니다. 다만 어디서부터 어디까지가 **단일 객체의 책임**인지, 불필요한 파일의 분리가 일어나는지에 대한 답은 정해진 정답이랄게 없어 이 부분에 대한 고민이 정말 많았습니다.

결국 개별 파일로 나눌 필요가 느껴지는 모듈은 크게 **파싱 객체 / 자동차 객체 / 경주 객체** 세개로 나뉜다고 생각했고, 밸리데이팅은 글로벌한 요소가 없고 각 객체의 책임이라 판단해 별도로 분리하지 않았습니다. 그와 함께 각 메소드의 이름을 최대한 구체화해 기능을 파악하는데 어려움이 없도록 노력했습니다.

### 3. 프라이빗 필드 / 캡슐화와 정적 메소드
Car 객체의 이름과 Race 객체의 자동차, 시도 횟수 등의 영역과 내부에서만 이용되는 메소드들은 외부에서 개입할 이유가 없기 때문에 모두 **프라이빗 필드**로 지정해 외부로부터의 예상치 못한 동작을 막고, 최대한 **캡슐화**하도록 노력했습니다. 인스턴스의 생성 없이도 호출이 가능한 메소드들도 **정적으로 표현**할 수 있도록 신경썼습니다.
